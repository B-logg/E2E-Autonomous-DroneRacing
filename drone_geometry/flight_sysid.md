# INAIR 레이서 비행 로그 식별 결과 (2026-11-16)

수동 비행 Blackbox 로그(2026-11-15 비행)로 구한 실기체 값입니다. 형상과 질량은 [hardware_spec.md](hardware_spec.md)에 있습니다.

- 원본 로그: `hierarchy_control/manual_flight_logs/LOGS/LOG0000{1..9}.BFL.csv`
- 계산 스크립트와 결과 JSON: `hierarchy_control/sysid/` (`python3 fit_*.py`로 다시 계산할 수 있습니다)

## 로그 구성

| 로그 | 내용 | 길이 | 기록 |
|---|---|---|---|
| LOG1, LOG2 | 지상 ARM 테스트 | 0.2 s, 5.3 s | 1 kHz |
| LOG3 | 호버 (약간의 기동 포함) | 38 s | 2 kHz |
| LOG4 | 펀치 1회 (6.7 s). 끝(38.6 s)에 충돌 또는 거친 착지 | 39 s | 2 kHz |
| LOG5 | 펀치 1회 (8.5 s) 후 호버 | 45 s | 2 kHz |
| LOG6 | 트랙 비행 (요 입력 거의 없음) | 152 s | 2 kHz |
| LOG7 | 트랙 비행, 84–96 s에 짧은 펀치 후 throttle 끊기 5회 | 113 s | 2 kHz |
| LOG8, LOG9 | 정지 (모터 꺼짐, USB 전원). `debug_mode` 20 = GYRO_RAW | 6 s, 124 s | 2 kHz |

- LOG3–7은 **같은 배터리 하나로 이어서 비행**했습니다. 무부하 전압이 25.1 V에서 22.2 V로 내려갑니다.
- **모든 비행은 Angle 모드**입니다(`flightModeFlags` = 3, ARM + ANGLE).
  - Betaflight 4.4.3이 기록하는 `setpoint`는 PID가 실제로 추종한 rate 명령입니다. `axisError`가 정확히 `setpoint − gyroADC`라서 확인됩니다.
  - 그래서 Angle 모드여도 rate 루프 응답(setpoint → gyro)은 식별할 수 있습니다.

## 집단 추력 모델 (펀치·throttle 끊기 9회 + 호버 5155 샘플)

FC 가속도의 z축 비추력(g)을 다음 모델로 맞췄습니다.

    a_z = PT1_τ( k1·w + k2·w² ) (지연 d 후) − c_v · v_z,    w = throttle × V / 22.2

| 항목 | 값 | 비고 |
|---|---|---|
| k1, k2 | 2.01, 3.95 | 전압 지수 β = 1 고정 (아래 한계 참고) |
| 22.2 V에서 정적 최대 비추력 | **5.96 g** | 25.2 V 7.4 g, 21.0 V 5.4 g (전압 강하 전 값) |
| 추력대중량비 (실측) | **약 5.5–6** | 펀치 중 실측 최대 5.2 g. 20.7–21.4 V로 강하된 상태이고 이미 상승 중이라 손실 포함 |
| 지연 + 추력 시정수 | τ 23 ms + 지연 10 ms (합 약 33 ms) | 둘의 비율은 불확실. 한 로그씩 빼고 맞추면 (11, 19), (21, 10), (37, 0) ms. 합은 30–37 ms로 안정 |
| 상승 속도에 따른 추력 손실 | 0.084 g / (m/s) | 프롭 유입 손실 + 항력. 펀치 중 5.2 g → 0.7 s 뒤 2.6 g |
| 호버 throttle 예측 | 25.2 V 0.273, 23.0 V 0.299, 22.2 V 0.309 | 실측보다 약 0.01 낮음 (호버 잔차 +0.02 g) |
| 오차 | 이벤트 0.29 g RMS, 호버 0.05 g RMS | |

- 시정수 τ에는 FC 가속도 필터(25 Hz, 약 6 ms)가 들어 있습니다.
- 정책도 같은 필터를 거친 가속도를 보므로, 시뮬에서는 필터를 따로 모델링합니다.
- **한계:** 전압 지수 β를 자유롭게 두면 펀치 데이터는 β → 0을, 호버 데이터는 β ≈ 1을 요구합니다.
  - 고 throttle에서 추력이 포화되는 현상(ESC나 전류 한계)이 섞인 것으로 보입니다.
  - 그래서 물리적인 값 β = 1로 고정했고, 시뮬에서 최대 추력을 넓게 랜덤화해 이 불확실성을 덮습니다.

## Rate 루프 응답 (Betaflight PID setpoint → 필터 후 gyro)

1–10 Hz 주파수 응답을 coherence 가중으로 맞췄습니다. 이 범위는 coherence가 0.6 이상입니다.

| 축 | 모델 | 1–10 Hz 등가 지연 | −3 dB | 비고 |
|---|---|---|---|---|
| roll | 2차, fn 18.3 Hz, ζ 0.49, 이득 1.03 | 약 8–12 ms | 약 24 Hz | 10–15 Hz에서 이득 1.3–1.4 공진 |
| pitch | 2차, fn 11.0 Hz, ζ 0.51, 이득 1.11 | 약 18–20 ms | 약 15 Hz | roll보다 느림. 앞뒤로 긴 기체라 pitch 관성이 큰 것으로 봄 |
| yaw | PT1, τ 21.6 ms, 이득 1.07 | 약 20 ms | 약 9 Hz | 요 입력이 작아서(setpoint 표준편차 2 °/s) 신뢰도 낮음 |

- **한계 1:** Angle 모드라 setpoint가 자세 오차에 반응해 만들어집니다. 그래서 10 Hz 이상은 coherence가 낮아 쓸 수 없습니다.
- **한계 2:** 이 응답은 Angle 모드(feedforward 포함, 로그 설정 그대로)에서 식별했습니다. 배포도 같은 Angle 모드·같은 설정이므로 추가 확인 비행은 필요 없습니다. Acro 모드로 바꾸면 다시 식별해야 합니다.
- **한계 3:** 비행 중 측정된 최대 각가속도는 roll 47, pitch 44, yaw 33 rad/s²로, 부드러운 비행이라 하한값일 뿐입니다. 기체의 실제 한계는 측정되지 않았습니다.

## FC 자세 추정기와 Angle 루프 (LOG3–7, `sysid/fc_attitude.py`, `sysid/fit_angle_chain.py`)

Betaflight 4.4는 자세 추정값을 로그에 남기지 않습니다. CSV의 `heading[]`은 Blackbox Explorer가 자체 계산한 값이라 FC 값이 아닙니다(실제로 Angle 루프 관계가 성립하지 않습니다). 그래서 Betaflight의 추정기(imu.c, Mahony)를 로그의 자이로·가속도로 다시 돌렸습니다. 검증은 Angle 모드의 PID setpoint가 `setpoint = 게인 × (한계각 × 스틱 − FC 자세)`(pid.c pidLevel)를 샘플 단위로 만족하는지로 했습니다.

| 항목 | 값 | 근거 |
|---|---|---|
| 추정기 | Mahony, 100 Hz, 주기 평균 자이로·가속도, 적분항 없음 | imu.c, 재현 R² |
| 보정 게인 kp | **0.25** (0.20–0.25에서 최적. FC CLI `imu_dcm_kp` = 2500으로 확인) | kp별 level 루프 R² (0: 0.95, 0.25: 0.994, 1.0: 0.78) |
| 가속도 사용 조건 | \|acc\| 0.9–1.1 g일 때만 | 조건을 빼면 R²가 0.99 → 0.78–0.92로 떨어짐 |
| 비행 중 가속도 사용 비율 | 29–50% | LOG3–7 |
| level 게인 | **4.9 /s** (로그별 4.81–4.95, levelPID P 50 → 5.0) | setpoint 회귀, R² 0.984–0.998 |
| 각도 한계 | **55°** (55.0–55.8, 기본값) | 같음 |
| 트림 오프셋 | ±0.2° 이내 (사실상 0) | 같음 |
| 부호 | roll: Betaflight = FRD. **pitch: Betaflight = −FRD** (Betaflight는 기수 내림이 +) | JAX/numpy 추정기 비교 |

**추정이 끌려가는 크기 (가속 구간):** 3 s 구간마다 자이로만 적분한 자세와 FC 추정을 비교했습니다.
- 3 s 구간: 중앙값 roll 0.5° / pitch 1.1°, p90 2.3° / 3.0°, 최대 5.3° / 5.6°
- 10 s 구간: p90 4.2° / 5.8°, 최대 7.7° / 7.1°
- 자이로 잔여 바이어스(0.4 °/s 미만)에 의한 적분 오차가 3 s에 약 1° 섞여 있습니다. 그래서 이 값은 FC 오차의 크기 규모로 봐야 합니다.

**정지 기울기 (LOG9):**
- 가속도가 (−0.008, −0.015, 0.998) g입니다.
- FC가 보는 기울기는 roll −0.9°, pitch +0.5°입니다. 장착 오차와 바닥 기울기가 섞여 있습니다.

## 아직 측정하지 않은 것

1. **실제 자세(외부 기준)**
   - 모캡이 없어 FC 추정의 절대 오차는 직접 재지 못했습니다.
   - 위의 끌림 크기와 시뮬 오차 분포가 같은 규모라는 것까지만 확인했습니다.
2. **Jetson → FC 명령 지연**
   - MSP RC override와 RC smoothing을 거칩니다.
   - 시뮬에서는 1–2 제어 스텝으로 랜덤화했습니다.
3. **카메라 → 마스크 지연**
   - 시뮬에서는 20–50 ms로 랜덤화했습니다.
4. **각가속도 한계와 관성**
   - 지금 값은 추정입니다.
   - 공격적인 Acro 축 입력 비행 로그가 있으면 확정할 수 있습니다.
5. **수평 항력**
   - 로그에 속도가 없어서 식별할 수 없습니다.
   - 시뮬은 SkyDreamer 값을 기준으로 ±50% 랜덤화했습니다.
